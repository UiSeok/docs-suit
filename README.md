# docs-suit

문서에 입히는 옷(suit)입니다. 도구 모음을 뜻하는 suite 가 아닙니다.

AI 에게 글을 맡길 때 매번 "합쇼체로, 결론 먼저, 출처는 각주로" 를 다시 쓰지 않도록, 글의 모양과 말투를 축으로 나눠 갈아입히는 테마 엔진입니다. 처음 받으면 게임에서 캐릭터를 만들듯 클래스(직업)를 고르고 페르소나를 입력합니다. 그다음 문서 종류만 말하면 클래스와 독자, 문서 종류에 맞는 규칙을 골라 AI 에게 줄 지침 한 장으로 조립합니다.

출력은 마크다운 지침 한 장이라서 어떤 AI 에도 붙습니다. Claude Code, Codex, Antigravity CLI, Grok Build, Cursor 는 공용 규격인 Agent Skills(`SKILL.md`)로, ChatGPT 와 Claude, Gemini, Grok 웹 채팅은 붙여 넣기로 씁니다.

## 처음 받았을 때

파이썬 3.9 이상만 있으면 되고, 따로 설치할 패키지는 없습니다.

```sh
git clone https://github.com/dodokim-lab/docs-suit.git && cd docs-suit
python3 suit.py bootstrap
```

bootstrap 은 네 단계를 묻습니다.
1. 클래스 고르기. 클래스가 기본 말투와 주력 문서를 정합니다. 다른 사람이 기여한 테마 조합으로 시작할 수도 있습니다.
2. 페르소나 여섯 가지. 호칭, 소속, 목표, 자주 쓰는 문서, AI 가 모르는 나, 싫어하는 말투입니다. 답하기 싫은 것은 넘어갑니다.
3. 쓰는 AI 도구 고르기. 고른 도구에 docs-suit 스킬을 설치합니다.
4. 캐릭터 고르기. 도트 그림 A 와 B 가운데 하나를 고릅니다.

답은 기본 슬롯인 `~/.config/docs-suit/profile.yaml` 에 남습니다. 저장소 밖이라 실수로 커밋되지 않습니다. 에이전트에게 "docs-suit 세팅해 줘" 라고 해도 됩니다. 스킬이 같은 질문을 대신 묻고 `bootstrap --class … --yes` 로 저장합니다.

## 클래스

| 클래스 | 이런 사람 | 주력 문서 |
|---|---|---|
| 학생 | 과제와 수행평가, 조별 활동, 발표를 하는 중고등학생과 대학생 | 보고서, 발표 자료, 발표 원고, 회의록·공유자료, 메일 |
| 취업 준비생 | 이력서와 자기소개서, 포트폴리오로 문을 두드리는 사람 | 이력서, 자기소개서, 포트폴리오, 면접 답변 |
| 대학원생·연구자 | 논문과 연구계획서, 학회 발표를 쓰는 사람 | 논문 초록, 연구계획서, 보고서, 발표 자료 |
| 개발자 | 설계 문서와 PR, 장애 회고, 기술 글을 쓰는 사람 | 설계 문서, PR 설명, 사건 회고, 블로그·기술 글, 가이드·README·위키 |
| 기획자·PM | 기획서와 회의록, 진행 보고로 사람들을 한 방향으로 모으는 사람 | 기획서, 회의록, 업무 보고, 발표 자료, 공지 |
| 직장인 | 업무 보고와 메일, 회의록을 매일 쓰는 사람 | 업무 보고, 메일, 회의록, 발표 자료, 공지 |
| 크리에이터 | 블로그와 뉴스레터, SNS 로 독자를 만나는 사람 | 블로그, 뉴스레터, SNS 글 |

주력이 아닌 문서도 모두 쓸 수 있습니다. 문서 종류는 스물한 가지이고 `python3 suit.py list` 로 봅니다.

## 쓰는 법

```sh
python3 suit.py compose --kind report                    # 보고서 지침 조립
python3 suit.py compose --kind cover-letter --chars 1000 # 자기소개서, 공백 포함 1,000자 제한
python3 suit.py compose --kind pr --set register=polite  # 축 하나만 바꿔 입기
python3 suit.py compose --kind email --revise            # 받은 원문을 메일 틀에 맞게 다듬기
python3 suit.py compose --kind notice --set markup=plain # 마크다운이 안 먹는 메신저에 올릴 공지
python3 suit.py compose --class researcher --kind slides # 이번만 다른 클래스로
python3 suit.py get --kind spec                          # 축마다 어떤 값이 어디서 왔는지
python3 suit.py set register haeyo --audience teammate   # 팀원에게는 해요체로 남기기
python3 suit.py export --agent claude,codex              # 도구에 스킬 다시 설치
python3 suit.py export --agent web                       # 웹 채팅용 지침을 파일로
```

| 도구 | 연결 |
|---|---|
| Claude Code | `~/.claude/skills/docs-suit/SKILL.md`. output style 로 쓰려면 `compose --format output-style -o ~/.claude/output-styles/<이름>.md` |
| Codex CLI | `~/.agents/skills/docs-suit/SKILL.md` |
| Antigravity CLI | `~/.gemini/config/skills/docs-suit/SKILL.md`. suit.py 실행을 물으면 항상 허용을 고른다 |
| Cursor | `~/.cursor/skills/docs-suit/SKILL.md` |
| Grok Build | Claude 자리와 공용 자리에 함께 설치 |
| 웹 채팅 | `export --agent web` 이 만든 지침이나 웹 고르개에서 복사한 지침을 맞춤 지침, 프로젝트, Gem 에 붙여 넣기 |

Claude Code, Antigravity CLI, Codex CLI 는 실제 요청을 넣어 스킬이 불리는 것을 확인했습니다. 결과는 `tests/agent/results/` 에 있습니다. Codex CLI 는 ChatGPT 무료 요금제로도 됩니다. Codex 는 홈 폴더의 `~/.agents/skills/` 까지 확인했고, Antigravity 는 작업 폴더의 `.agents/skills/` 로 확인했습니다. Antigravity 의 전역 자리와 나머지 도구의 자리는 2차 자료 기준이라 각 도구 문서로 확인이 필요합니다. 스킬 파일은 이 저장소의 `suit.py` 를 절대 경로로 부르므로, `git pull` 하면 모든 도구에 바로 반영됩니다. 저장소를 옮겼다면 `export` 를 다시 돌립니다.

## 다 쓴 글을 재고 검토받기

에이전트는 문서를 다 쓴 뒤 `check` 로 본문이 조립한 규칙을 지켰는지 잽니다. 결과는 두 층으로 나옵니다.

| 표시 | 뜻 | 재는 것 |
|---|---|---|
| `✗` | 고쳐 쓰고 다시 잰다 | 축의 값, 서식 없음 문서에 남은 마크다운 기호, 틀이 꼭 쓰라고 한 절, 대시, 이중 피동, 예고와 인사, 수사 서술어, 남은 자리표시, 본문에 적힌 키와 비밀번호 |
| `△` | 보여 주기만 한다 | "X 가 아니라 Y" 대구의 반복, "중요한 것은" 과 "결론적으로" 같은 상투 표현, 정보 없는 수식어, 잦은 연결어미 쉼표, 긴 문장과 토막 문장 |

`△` 는 사람 글에도 흔한 표현이라 고칠지는 글을 보고 정하고, 고치지 않아도 검사는 통과합니다. 패턴은 `themes/ko/tells.yaml` 에 있고, 따옴표와 백틱, 코드 블록 안의 예문은 세지 않습니다.

이 검사는 AI 가 썼는지 가리는 판정기가 아닙니다. 공통 바닥의 문장 규칙을 재는 자입니다. 단어만 고친 글은 여전히 AI 가 쓴 티가 난다는 실험 결과가 있어서, 공통 바닥에는 일반론 대신 받은 자료의 사례와 수치로 쓰라는 규칙도 함께 둡니다.

다 쓴 글을 따로 검토받고 싶으면 `review` 가 같은 규칙으로 채점하는 검토 지침을 만듭니다. 글을 쓴 대화를 모르는 새 대화나 서브에이전트에 넘겨야 검토자가 쓴 사람의 전제를 그대로 믿지 않습니다. 에이전트에게 "이 글 검토해 줘" 라고 하면, 서브에이전트를 띄울 수 있는 도구에서는 스킬이 대신 넘깁니다.

```sh
python3 suit.py check 초안.md --kind design-doc                     # ✗ 와 △ 로 잰다
python3 suit.py review 초안.md --kind cover-letter --source 공고.md  # 원문과 본문을 빈자리에 넣은 검토 지침
```

## 프로필을 여러 개 두고 폴더마다 고르기

회사 일과 개인 작업처럼 쓰는 사람이 달라지면 프로필을 슬롯으로 나눕니다. 기본 슬롯은 `profile.yaml` 이고, 이름 붙은 슬롯은 `~/.config/docs-suit/profiles/<이름>.yaml` 에 생깁니다.

```sh
python3 suit.py bootstrap --profile work   # work 슬롯을 새로 만든다
python3 suit.py profile list               # 슬롯 목록. * 가 지금 쓰는 슬롯
python3 suit.py profile use work           # 어느 폴더에서든 work 슬롯을 쓴다
cd ~/작업폴더
python3 <docs-suit 경로>/suit.py profile use work --here    # 이 폴더에서만 work 슬롯
python3 <docs-suit 경로>/suit.py set register plain --here  # 이 폴더에서만 평어체
```

`--here` 는 그 폴더에 `.docs-suit.yaml` 을 만듭니다. 엔진은 지금 폴더부터 홈 폴더까지 올라가며 이 파일들을 겹쳐 읽고, 가까운 폴더의 값이 이깁니다. 에이전트는 작업 폴더에서 엔진을 부르므로 Claude Code, Codex, Antigravity 어디서든 같은 설정이 적용됩니다.

폴더 파일에는 쓸 슬롯 이름과 축 값만 들어갑니다. 페르소나는 넣지 않으므로, 저장소에 함께 올려 팀이 같은 문서 규칙을 써도 개인정보가 새지 않습니다.

슬롯은 아래 순서로 정하고, 앞의 것이 이깁니다.
1. 환경 변수 `DOCS_SUIT_PROFILE` 이 가리키는 파일
2. `--profile` 인자
3. 폴더 파일의 `profile`
4. `profile use` 로 고른 슬롯
5. 기본 슬롯

## 문서를 쓸수록 캐릭터가 자랍니다

슬롯이 곧 캐릭터입니다. 캐릭터는 도트 그림 A 와 B 중 하나로 시작하고, 클래스는 칭호로 드러납니다. 에이전트는 문서를 다 쓴 뒤 `check` 로 본문이 조립한 규칙을 지켰는지 재고, 어긋난 곳이 있으면 한 번 고쳐 쓴 뒤 결과를 성장 기록에 남깁니다. 경험치는 글의 양이 아니라 글이 나아진 신호로 셉니다.

| 한 일 | 경험치 |
|---|---|
| 문서 한 건을 마침 | 10 |
| 잰 규칙을 모두 지킴 | 10 |
| 남은 `[확인 필요]` 를 채우고 다시 검사 | 5 |
| 처음 써 본 문서 종류 | 20 |

같은 문서를 고쳐 다시 검사하면 그 문서의 기록 가운데 가장 좋은 것 하나로 셉니다. 같은 날 같은 종류는 두 건까지만 세고, 연속 기록은 두지 않으며, 경험치는 깎이지 않습니다. 규칙은 `themes/ko/growth.yaml` 에 있고, 고치면 지난 기록에도 새 규칙이 적용됩니다.

레벨이 오르면 전직해 칭호가 바뀌고, 전직할 때마다 꾸밀 거리가 하나씩 열립니다. 1차와 2차는 레벨만 차면 오르고, 3차와 4차는 이 저장소에 기여하고 받는 승급 키가 있어야 오릅니다.

| 단계 | 조건 | 직장인 칭호 | 새로 열리는 꾸미기 |
|---|---|---|---|
| 기본 | 처음 | 사원 | 캐릭터 A, B 는 언제든 바꾼다 |
| 1차 | Lv.10 | 대리 | 옷 색 |
| 2차 | Lv.20 | 과장 | 머리 모양 |
| 3차 | Lv.30 과 기여 승급 키 | 차장 | 소품 |
| 4차 | Lv.50 과 테마 조합 기여 승급 키 | 부장 | 옷 모양 |

한 레벨에 드는 경험치는 전직 구간마다 50, 65, 80, 100, 120 으로 조금씩 가팔라지고, 최고 레벨은 Lv.100 입니다. 문서 한 건이 20점쯤이니 1차까지 20건 남짓, 4차 문턱인 Lv.50 까지 200건쯤 씁니다.

칭호는 클래스마다 다릅니다. 대학원생·연구자는 대학원생, 석사, 박사, 박사후연구원, 예비교수로 오르고, 나머지 클래스의 칭호는 `themes/ko/classes/` 에 있습니다.

```sh
python3 suit.py check 보고서.md --kind work-report   # 본문이 규칙을 지켰는지 재고 기록한다. --no-record 는 재기만 한다
python3 suit.py card                                # 캐릭터 카드. 터미널에서는 도트 그림이 함께 나온다
python3 suit.py look                                # 지금 꾸미기와 열린 부위, 고를 수 있는 값
python3 suit.py look base b                         # 캐릭터 B 로 바꾼다
python3 suit.py look color wine                     # 1차 전직 뒤 옷 색을 와인색으로
python3 suit.py growth off                          # 캐릭터 키우기를 끈다. 지난 기록은 남는다
```

기록은 `~/.config/docs-suit/growth/<슬롯>.jsonl` 에 남습니다. 날짜와 문서 종류, 검사 결과, 남은 `[확인 필요]` 개수만 적고 본문과 파일 경로는 남기지 않습니다. 에이전트는 성장 줄을 답 끝에만 붙이고 문서 본문에는 넣지 않습니다. 그림은 `themes/ko/sprites/` 에 기본 몸과 옷, 머리, 소품 부품으로 나뉘어 있고, 부품을 더하면 `themes/ko/look.yaml` 에 한 줄을 더합니다.

## 세션을 열면 캐릭터가 뜨게 하기

Claude Code 는 화면 맨 아래 상태 줄에 캐릭터를 그릴 수 있습니다. 상태 줄은 세션을 여는 순간 그려지고 작업 폴더의 슬롯을 따라가므로, 폴더마다 그 폴더의 캐릭터가 뜹니다. `~/.claude/settings.json` 에 아래를 넣습니다.

```json
"statusLine": {"type": "command", "command": "python3 <docs-suit 경로>/suit.py status"}
```

이미 쓰는 상태 줄 스크립트가 있으면 바꾸지 말고, 스크립트가 받은 JSON 을 그대로 넘기는 줄을 끝에 더합니다. 예를 들어 `input=$(cat)` 으로 받는 스크립트라면 `printf '%s' "$input" | python3 <docs-suit 경로>/suit.py status` 입니다. 스크립트의 마지막 명령이 0 이 아닌 코드로 끝나면 Claude Code 가 상태 줄을 통째로 비우므로, `[ … ] && …` 꼴로 끝내지 말고 `if` 문을 씁니다. 기본은 얼굴과 칭호, 레벨을 일곱 줄로 그리고, `--size line` 은 글 한 줄, `--size full` 은 온몸입니다. 슬롯이 없거나 캐릭터 키우기를 끈 폴더에서는 아무것도 그리지 않습니다.

Antigravity CLI 도 `~/.gemini/antigravity-cli/settings.json` 의 `statusLine` 에 같은 명령을 걸 수 있다고 문서에 나와 있지만 아직 직접 확인하지 않았습니다.

Codex CLI 는 상태 줄에 외부 명령을 걸 수 없어서 터미널 옆 칸에 캐릭터 창을 띄웁니다. 캐릭터 창은 성장 기록과 슬롯 파일만 읽으므로 어느 에이전트로 문서를 쓰든 1초 안에 다시 그려지고, 방금 오른 경험치와 전직을 아래에 보여 줍니다.

```sh
python3 <docs-suit 경로>/suit.py widget --split && codex   # herdr 나 tmux 안이면 오른쪽에 칸을 나눠 띄우고 Codex 를 연다
python3 <docs-suit 경로>/suit.py widget                    # 터미널 앱의 창 나누기로 연 옆 칸에서 직접 띄운다
```

칸이 좁으면 그림 아래로 글을 내립니다. 창은 그 칸에서 Ctrl+C 로 닫습니다.

Codex 를 열 때마다 저절로 띄우려면 `~/.codex/hooks.json` 에 훅 두 개를 겁니다. 처음 한 번은 Codex 안에서 `/hooks` 로 이 훅을 신뢰한다고 승인해야 돌기 시작합니다.

```json
{
  "hooks": {
    "SessionStart": [{"matcher": "startup|resume", "hooks": [
      {"type": "command", "command": "python3 <docs-suit 경로>/suit.py widget --split --auto", "timeout": 10}]}],
    "SessionEnd": [{"hooks": [
      {"type": "command", "command": "python3 <docs-suit 경로>/suit.py widget --close --auto", "timeout": 3}]}]
  }
}
```

자동으로 띄우는 창은 `.docs-suit.yaml` 이 있는 폴더에서만 열리므로, 상관없는 프로젝트에서 Codex 를 열면 칸이 생기지 않습니다. 같은 칸 옆에 창이 이미 떠 있으면 다시 나누지 않고, Codex 가 끝나면 창이 든 칸도 닫힙니다. 훅은 아무것도 출력하지 않아 Codex 가 받는 맥락을 어지럽히지 않습니다. herdr 칸 안에서 tmux 를 돌리면 가장 안쪽인 tmux 칸을 나눕니다.

## 테마 조합과 승급 키

테마 조합은 축 기본값과 독자별 값을 한 묶음으로 남긴 것입니다. 게임의 스킬 조합처럼 다른 사람이 기여한 조합을 내 슬롯에 입힐 수 있고, 처음 캐릭터를 만들 때 추천 조합으로 시작할 수도 있습니다. 조합은 `themes/ko/presets/` 에 있습니다.

```sh
python3 suit.py preset list                 # 조합 목록. 추천 표시가 있는 것이 앞에 온다
python3 suit.py preset show weekly-brief    # 조합의 축 값
python3 suit.py preset use weekly-brief     # 내 슬롯에 입힌다. 이전 슬롯은 .bak 으로 남는다
```

3차와 4차 전직은 이 저장소에 기여해야 열립니다.
- 3차는 종류를 가리지 않고 한 번 기여하면 열립니다. 오타 하나를 고친 PR 이라도 머지되면 됩니다.
- 4차는 내 테마 조합의 기여입니다. `python3 suit.py preset export <이름> --by <GitHub 아이디> --desc "쓰임새 한 줄"` 이 지금 내 설정을 조합 파일로 뽑아 주고, 그 파일을 `themes/ko/presets/` 에 넣어 PR 을 보냅니다. 페르소나는 들어가지 않습니다.

PR 이 머지되면 관리자가 PR 댓글로 승급 키를 드립니다. `python3 suit.py promote <키>` 로 넣으면 레벨이 찬 만큼 전직하고, 카드에 기여한 GitHub 아이디가 붙습니다. 키는 GitHub 아이디와 차수, 기여 링크에 관리자의 서명을 붙인 문자열이고, 엔진은 저장소에 든 공개 키로 서명을 확인합니다. 엔진과 기록이 모두 내 컴퓨터에 있으니 코드를 고치면 얼마든지 올릴 수 있지만, 그러면 혼자 하는 게임의 재미만 줄어듭니다.

## 화면에서 고르고 바로 적용하기

초기 세팅이나 테마를 바꿀 때는 웹 화면을 내 컴퓨터에 띄우면, 복사하거나 내려받지 않고 바로 적용됩니다.

```sh
cd ~/작업폴더
python3 <docs-suit 경로>/suit.py serve               # 테마 고르기 화면이 열린다
python3 <docs-suit 경로>/suit.py serve --page create # 캐릭터 만들기 화면이 열린다
```

실행한 폴더 기준의 슬롯에 바로 쓰고, 화면 맨 위 띠에서 다른 슬롯도 고를 수 있습니다. 테마 고르기에서 "고른 값을 슬롯에 저장"을 누르면 슬롯의 기본값이 바뀌고, "실행한 폴더에만"을 켜면 그 폴더의 `.docs-suit.yaml` 에 남습니다. 캐릭터 만들기의 "이 컴퓨터에 저장"은 슬롯 파일을 쓰고 이전 파일을 `.bak` 으로 남기며, 원하면 그 폴더가 이 슬롯을 쓰게 하고 고른 도구에 스킬까지 깝니다. 에이전트에게 "docs-suit 화면 열어 줘"라고 해도 띄워 줍니다.

화면 서버는 이 컴퓨터(127.0.0.1)에서만 받고, 띄울 때마다 바뀌는 열쇠를 화면에 심어 그 열쇠가 없는 요청은 거절합니다. 브라우저에 열린 다른 사이트가 내 프로필을 고치지 못하게 하기 위해서입니다. 30분 동안 쓰지 않으면 스스로 꺼지고, 화면의 "끄기"로 바로 끌 수도 있습니다.

## 웹 고르개

캐릭터 만들기 화면(`create.html`)에서는 클래스, 시작 조합, 캐릭터 A·B, 페르소나, 쓰는 도구를 차례로 고르면 오른쪽에 캐릭터와 칭호가 그려지고, 슬롯 파일을 내려받거나 웹 채팅에 붙일 지침을 복사합니다. 내려받은 슬롯 파일은 `bootstrap` 이 만드는 것과 같습니다.

테마 고르기 화면도 설치 없이 씁니다. 클래스와 문서 종류, 독자를 칩으로 고르면, 축마다 같은 예문을 값별로 써 본 카드가 나란히 보입니다. 평어체와 합쇼체, 해요체가 같은 문장에서 어떻게 달라지는지, 발표 디자인 세 가지가 같은 슬라이드에서 어떻게 보이는지 보고 누르면 됩니다. 오른쪽에서 조립된 지침을 복사합니다. GitHub Pages 주소는 https://dodokim-lab.github.io/docs-suit/ 이고, 로컬에서는 `docs` 폴더에서 `python3 -m http.server` 를 띄웁니다.

어떤 옷을 입어도 지키는 공통 바닥이 있습니다. 모르면 지어내지 않고 `[확인 필요]` 로 남기기, 확인한 사실과 추정을 섞지 않기, 수치를 지어내지 않기 같은 사실 규칙이 먼저 옵니다. 그 뒤로 쓰기 전에 무엇을 물을지, 문장을 어디서 잇고 끊을지, 어떤 상투 표현을 피할지가 이어집니다. 문장 규칙은 한국어 AI 말투를 실측한 공개 프로젝트들과 만든 사람의 문체 프로필을 견줘 겹치는 것을 골랐고, 출처는 `themes/ko/PROVENANCE.md` 에 있습니다.

## 값은 이 순서로 정해집니다

위에 있는 것이 이깁니다.

1. 문서 종류가 고정한 축
2. 직접 고른 값 (`--set`, 웹에서 누른 카드)
3. 프로필의 독자별 값
4. 문서 종류가 권하는 값
5. 프로필의 기본값
6. 독자 프로필
7. 클래스 기본값
8. 중립 기본값

클래스를 독자보다 아래에 둔 까닭은, 어법이나 용어 수준은 쓰는 사람보다 읽는 사람이 정하는 게 맞기 때문입니다. 공개 범위는 예외입니다. 개인정보가 새지 않게 하려는 안전 축이라서, 직접 고른 값과 프로필은 더 조심하는 쪽으로 바꿀 때만 이깁니다. 가장 조심하는 쪽은 인터넷 공개이고, 팀 안에서만 볼 글이면 독자를 팀원·동료나 동료 개발자로 고릅니다.

페르소나는 지침의 "쓰는 사람" 절에 실리고, AI 가 관점과 예시를 고르는 데만 씁니다. 직접 넣으라고 하지 않는 한 본문에 옮겨 적지 않도록 지침에 적어 둡니다.

## 내 옷을 만들어 입기

이 저장소를 fork 해서 `themes/ko/` 아래 문서를 고치면 그대로 내 테마가 됩니다.
- 값을 새로 만들 때는 `themes/ko/<축>/<값>.md` 를 만들고 `axes.yaml` 에 한 줄 더합니다. 문서 끝 `## 보기` 절에 공통 예문을 그 값으로 써 두면 웹 고르개가 카드로 보여 줍니다. 보기 절은 AI 에게 주는 지침에는 실리지 않습니다.
- 클래스는 `themes/ko/classes/<id>.yaml`, 문서 종류는 `defaults.yaml` 과 `kinds/<종류>.md` 입니다.
- 본문 검사 패턴은 `tells.yaml`, 틀이 꼭 쓰라고 한 절은 `defaults.yaml` 의 `must` 입니다. 패턴을 더하면 selftest 가 모든 값의 보기에서 오류 패턴이 걸리지 않는지 잽니다.
- 고친 뒤 `python3 suit.py bundle` 로 웹 묶음을 다시 만들고, `python3 suit.py selftest` 와 `node tests/parity.js` 로 확인합니다. parity 는 웹과 엔진이 704가지 조합에서 같은 지침과 검토 지침을 내는지 글자 하나까지 견줍니다. GitHub Actions 도 같은 검사를 돌립니다.

## 함께 쓰면 좋은 것

- `starters/start.md`: 일을 맡길 때 첫 메시지. 상황과 이유는 요약하지 말고 줄글로 다 풀고, 꼭 지킬 조건만 목록으로 뽑습니다.
- `starters/review.md`: 다 쓴 글을 새 대화에서 처음 보는 채점자에게 검토받는 프롬프트입니다. 문서 종류와 축의 규칙까지 채점 기준에 넣으려면 `suit.py review` 를 씁니다.

## 비슷한 프로젝트와 다른 점

조립형 프롬프트 모음은 이미 있습니다. microsoft/PromptKit 은 페르소나와 형식을 조립하지만 엔지니어링 문서용이고, 문체와 독자 축은 없습니다. simonpainter/tone 은 공통 기준과 형식별 지침을 두지만 영어이고 조립 엔진이 없습니다. 한국어 AI 말투를 다루는 프로젝트로는 epoko77-ai/im-not-ai 와 devswha/patina 가 있고, 둘 다 이미 쓴 글을 고쳐 쓰는 데 집중합니다. docs-suit 는 한국어 어법과 클래스, 문서 종류, 독자를 축으로 다루고, 쓰기 전에 조립한 규칙으로 쓴 뒤에도 재며, 값마다 보기를 그려 눈으로 고르게 하며, 웹과 터미널, AI 코딩 도구가 같은 데이터로 같은 지침을 조립한다는 점이 다릅니다.
