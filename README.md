# 글옷 (geulot)

AI 에게 글을 맡길 때 매번 "합쇼체로, 결론 먼저, 출처는 각주로" 를 다시 쓰지 않도록, 글의 모양과 말투를 축으로 나눠 갈아입히는 테마 엔진입니다. 글옷은 글에 입히는 옷이라는 뜻입니다. 내용은 그대로 두고 문체와 어법, 골격, 분량, 디자인 같은 겉모양만 바꿔 입힙니다.

문서 종류와 독자를 고르면 축마다 맞는 규칙을 골라 AI 에게 줄 지침 한 장으로 조립합니다. 같은 규칙이라도 교수님께 내는 보고서와 팀원에게 돌리는 공유자료는 달라야 하고, 마음에 안 드는 축은 그 축만 바꾸면 됩니다. 첫 기본 프리셋은 대학생 문서이고, 다른 독자층의 프리셋은 같은 틀로 더할 수 있습니다.

## 보고 고릅니다

웹 고르개는 축마다 같은 예문을 값별로 써 본 카드를 나란히 보여 줍니다. 평어체와 합쇼체, 해요체가 같은 문장에서 어떻게 달라지는지, 발표 디자인 세 가지가 같은 슬라이드에서 어떻게 보이는지 눈으로 보고 누르면 됩니다. 문서 종류와 독자가 정한 값에는 "자동" 표시가 붙고, 직접 누른 카드에는 "고름" 표시가 붙습니다. 오른쪽에서 조립된 지침을 바로 복사합니다.

설치 없이 쓰려면 GitHub Pages 에 올린 웹 고르개를 엽니다. 저장소를 받았다면 `docs` 폴더에서 `python3 -m http.server` 를 띄우고 브라우저로 엽니다.

복사한 지침은 아래 자리에 붙여 넣습니다.
- ChatGPT: 설정의 맞춤형 지침, 또는 프로젝트 지침
- Claude: 프로젝트 지침, 또는 스타일 만들기의 "직접 설명"
- Gemini: Gem 만들기의 지침
- Claude Code: output style 형식으로 저장해 `~/.claude/output-styles/` 에 넣기

## 터미널과 AI 코딩 도구에서

파이썬 3.9 이상만 있으면 되고, 따로 설치할 패키지는 없습니다.

```sh
python3 theme.py list                                     # 문서 종류, 독자, 축과 값
python3 theme.py compose --kind report                    # 보고서 지침 조립
python3 theme.py compose --kind resume --chars 1000       # 이력서, 공백 포함 1,000자 제한
python3 theme.py compose --kind report --set skeleton=pcs --set register=polite
python3 theme.py get --kind slides                        # 축마다 어떤 값이 어디서 왔는지
python3 theme.py set register haeyo --audience teammate   # 내 설정: 팀원에게는 해요체
```

- Claude Code 스킬: `sh integrations/claude-skill/install.sh` 를 돌리면 `~/.claude/skills/doc-theme` 에 설치됩니다. 문서를 써 달라고 하면 스킬이 지침을 조립해 따릅니다.
- Claude Code output style: `python3 theme.py compose --kind report --format output-style -o ~/.claude/output-styles/report.md` 로 저장하고 `/config` 에서 고릅니다.
- Codex, Gemini CLI: `integrations/AGENTS-snippet.md` 의 조각을 `AGENTS.md` 나 `GEMINI.md` 에 붙입니다.

웹 고르개와 `theme.py` 는 같은 데이터로 같은 지침을 조립합니다. `node tests/parity.js` 가 두 쪽의 출력이 글자 하나까지 같은지 확인합니다.

## 축과 값

| 축 | 값 | 기본 프리셋 (대학생) |
|---|---|---|
| 디자인 · 문서 | Sakura, new.css | Sakura |
| 디자인 · 발표 | 종이 톤, 어두운 고대비, 흰 바탕 한 색 | 종이 톤 |
| 문체 | 줄글, 개조식 | 줄글 |
| 어법 | 평어체, 합쇼체, 해요체 | 평어체 |
| 용어 수준 | 일상어, 풀어 쓰고 전공어 곁들임, 전공 용어 그대로 | 풀어 쓰기 |
| 골격 | 결론 먼저, 시간순, 문제·원인·대책, 목적·방법·결과·고찰, 문제·해결·효과 | 결론 먼저 |
| 분량 | 짧게, 한 쪽, 상세. 글자수는 `--chars` 로 따로 겁니다 | 한 쪽 |
| 강조 | 굵은 글씨, 쓰지 않음 | 굵은 글씨 |
| 그림 | 표 먼저, mermaid, 그리지 않음 | 표 먼저 |
| 출처 표기 | 각주, 참고문헌(APA), 본문 링크 | 각주 |
| 공개 범위 | 인터넷 공개, 제출용, 팀 내부 | 인터넷 공개 |
| AI 사용 고지 | 각주로 밝힘, 부록으로 밝힘, 밝히지 않음 | 각주로 밝힘 |

어떤 테마를 골라도 지키는 공통 바닥이 따로 있습니다. 모르면 지어내지 않고 `[확인 필요]` 로 남기기, 확인한 사실과 추정을 섞지 않기, 수치를 지어내지 않기 같은 규칙입니다. 원문은 `themes/base.md` 에 있습니다.

## 문서 종류와 독자

| 문서 종류 | 기본 독자 | 종류가 고정하는 것 |
|---|---|---|
| 이력서 | 채용 담당·면접관 | 경험마다 문제·해결·효과로 쓰는 틀, AI 고지 없음 |
| 발표 PPT | 발표 청중 | 한 장에 메시지 하나인 틀, 개조식 |
| 보고서·레포트 | 교수·조교 | 없음. 골격은 목적·방법·결과·고찰을 권합니다 |
| 팀플 공유자료 | 팀원 | 결정·담당·기한 표로 쓰는 틀 |

독자는 교수·조교, 팀원, 채용 담당·면접관, 발표 청중, 인터넷 독자 다섯 가지입니다. 독자마다 문체와 어법, 용어 수준, 공개 범위의 기본값이 다릅니다.

## 값은 이 순서로 정해집니다

위에 있는 것이 이깁니다.

1. 문서 종류가 고정한 축
2. 직접 고른 값 (`--set`, 웹에서 누른 카드)
3. 내 설정의 독자 프로필
4. 문서 종류가 권하는 값
5. 내 설정의 기본값
6. 독자 프로필
7. 기본 프리셋

공개 범위는 예외입니다. 개인정보가 새지 않게 하려는 안전 축이라서, 직접 고른 값과 내 설정은 범위를 더 좁힐 때만 이깁니다. 팀 내부용으로 정해진 문서를 인터넷 공개로 바꾸는 것은 되지만, 제출용 보고서를 팀 내부로 넓히는 것은 되지 않습니다.

## 내 옷을 만들어 입기

이 저장소를 fork 해서 `themes/` 아래 규칙 문서를 고치면 그대로 내 테마가 됩니다.
- 값을 새로 만들 때는 `themes/<축>/<값>.md` 를 만들고 `themes/axes.yaml` 에 한 줄 더합니다. 문서 끝 `## 보기` 절에 공통 예문을 그 값으로 써 두면 웹 고르개가 카드로 보여 줍니다. 보기 절은 AI 에게 주는 지침에는 실리지 않습니다.
- 고친 뒤 `python3 theme.py bundle` 로 웹 묶음을 다시 만들고, `python3 theme.py selftest` 와 `node tests/parity.js` 로 확인합니다. GitHub Actions 도 같은 검사를 돌립니다.
- 같이 쓰고 싶은 값과 프리셋은 PR 로 보내 주세요. 학과나 직군마다 맞는 골격이 다르니 그런 값을 특히 반깁니다.

## 함께 쓰면 좋은 것

- `starters/start.md`: 일을 맡길 때 첫 메시지. 상황과 이유는 요약하지 말고 줄글로 다 풀고, 꼭 지킬 조건만 목록으로 뽑습니다.
- `starters/review.md`: 다 쓴 글을 새 대화에서 처음 보는 채점자에게 검토받는 프롬프트입니다.

## 비슷한 프로젝트와 다른 점

조립형 프롬프트 모음은 이미 있습니다. microsoft/PromptKit 은 페르소나와 형식을 조립하지만 엔지니어링 문서용이고, 문체와 독자 축은 없습니다. simonpainter/tone 은 공통 기준과 형식별 지침을 두지만 영어이고 조립 엔진이 없습니다. 글옷은 한국어 어법(평어체, 합쇼체, 해요체)과 문서 종류, 독자를 축으로 다루고, 값마다 보기를 그려 눈으로 고르게 하며, 웹과 터미널, AI 코딩 도구가 같은 데이터로 같은 지침을 조립한다는 점이 다릅니다.
