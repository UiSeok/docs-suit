# docs-suit

AI 와 문서를 쓰다 보면 AI 가 쓴 티가 묻어납니다.<br>
굵은 글씨로 강조한 라벨과 줄마다 붙은 이모지, 수식어를 잔뜩 붙이거나 "~가 넷입니다" 처럼 어색한 말투가 검토할 때마다 눈살을 찌푸리게 합니다.<br>
문서를 쓸 때마다 이걸 손으로 고치다 보니 너무 불편했습니다.

그래서 상황에 맞춰 글을 쓰게 하는 엔진을 만들었습니다.<br>
옷 입히기 게임처럼 읽는 사람과 문서 종류, 말투를 골라 문서마다 테마를 갈아입힙니다.<br>
글을 쓸수록 자라는 도트 캐릭터도 함께 있으니 열심히 키워 보세요!

## 같은 보고에서 AI 가 쓴 티가 빠집니다

팀장님께 올리는 정류장 대기 시간 조사 주간 보고를 예로 듭니다. 지침 없이 맡기면 이런 모양이 나오기 쉽습니다.

```markdown
# 📊 정류장 대기 시간 조사 주간 보고

안녕하세요! 이번 주 정류장 대기 시간 조사 진행 상황에 대해 알아보겠습니다.

## 1. 개요

이번 조사는 시민들의 대중교통 이용 편의성을 높이기 위한 중요한 프로젝트입니다. 다양한 시간대의 데이터를 효율적으로 수집해 의미 있는 인사이트를 도출하고자 했습니다.

## 2. 주요 성과

- **데이터 수집**: 다양한 시간대에 걸쳐 체계적인 데이터 수집을 완료했습니다 ✅
- **분석 결과**: 출근 시간대 평균 대기 시간이 12분으로, 다른 시간대 대비 약 2배 높은 것으로 나타났습니다 📈
- **원인 파악**: 배차 간격은 동일하나 승객이 집중되는 것으로 보여집니다 🔍

## 3. 향후 계획

결론적으로, 8시대 증차를 검토해 볼 수 있을 것으로 보입니다. 단순한 데이터 수집을 넘어 실질적인 개선안을 마련하는 것이 중요합니다.

도움이 되셨길 바랍니다! 😊
```

docs-suit 는 이 글이 상사에게 올리는 업무 보고라는 것을 받아 규칙을 조립합니다. 결론과 상태를 첫 줄에, 정해 주실 일을 둘째 줄에 두고, 그 아래를 한 일과 할 일, 막힌 것으로 나누는 틀입니다. 말투는 합쇼체이고 본문은 짧은 목록으로 씁니다. 그 규칙대로 쓰면 이렇게 됩니다.

```markdown
# 정류장 대기 시간 조사 주간 보고

출근 시간대 대기가 다른 시간대의 두 배로 확인돼 조사를 마쳤고, 대책 보고서를 쓰고 있습니다.
**금요일까지 8시대 1회 증차 여부를 정해 주셔야 합니다.** 배차 간격을 줄이는 안보다 비용이 적어 증차를 추천합니다.

이번 주 한 일
- 출근 시간대 평균 대기 12분, 다른 시간대의 2배
- 배차 간격은 그대로이고 8시대에 승객이 몰리는 것이 원인

다음 주 할 일
- 대책 보고서 초안 제출

막힌 것
- 증차 비용 견적, 운수사 회신 대기
```

같은 내용을 팀원에게 공유할 때는 문서 종류와 읽는 사람만 바꿔 다시 조립합니다. 진행 공유는 정한 일을 담당과 기한까지 표로 두고, 못 정한 것을 따로 모으는 틀입니다. 말투는 해요체로 바뀝니다.

```markdown
# 정류장 대기 시간 조사 진행 공유

조사를 마쳤고, 8시대 1회 증차 안을 팀장님께 올렸어요.

| 정한 것 | 담당 | 기한 |
|---|---|---|
| 운수사 증차 비용 견적 받아 공유 | 김사원 | 이번 주 목요일 |
| 대책 보고서 초안 작성 | 박대리 | 다음 주 수요일 |

아직 못 정한 것
- 8시대 증차 여부. 팀장님이 금요일까지 정해 주시기로 했어요.

조사에서 나온 것
- 출근 시간대 평균 대기 12분, 다른 시간대의 2배
- 배차 간격은 그대로인데 8시대에 승객이 몰리는 것이 원인

다음 모임은 다음 주 월요일이고, 그때까지 견적과 초안을 가져와요.
```

다 쓴 글은 같은 규칙으로 잽니다. 처음 글을 재면 ✗ 가 나와 다시 쓰게 하고, 뒤의 두 글은 통과합니다.

```
$ python3 suit.py check 보고.md --kind work-report --audience manager
검사 · 업무 보고 · 독자 상사·리더
✓ 어법: 합쇼체 6
✓ 문체: 목록 줄 43%
✓ 분량: 390자, 한도 1500자
✗ 문서 종류의 틀: 빠짐: 한 일, 할 일. 틀이 정한 절을 더한다
✗ 예고와 인사: 2곳 「…상황에 대해 알아보겠습니다. ## 1.…」. 예고와 인사를 빼고 바로 본론을 쓴다
△ 단순한 X 를 넘어: 1곳 「…로 보입니다. 단순한 데이터 수집을 넘어 실질적인 개선…」. 넘어선다는 말 대신 무엇을 하는지 쓴다
△ 맺음 상투어: 1곳 「…향후 계획 결론적으로, 8시대 증차…」. 맺음말로 되풀이하지 말고 결론을 앞에 둔다
△ 정보 없는 수식어: 3곳 「…로젝트입니다. 다양한 시간대의 데이…」. 구체적인 명사와 수치로 바꾼다
△ 겹친 완곡: 1곳 「…를 검토해 볼 수 있을 것으로 보입니다. 단…」. 근거만큼만 단정한다
△ 굵은 라벨 목록: 3곳 「…. 주요 성과 - **데이터 수집**: 다양한 시간대…」. 완결된 문장의 목록이나 줄글로 쓴다
△ 인사로 여는 글: 1곳 「…사 주간 보고 안녕하세요! 이번 주 정류…」. 인사 대신 첫 줄에 할 말을 바로 쓴다
```

## 비슷한 도구와 무엇이 다른가

비슷한 도구는 이미 있었지만 제 요구에는 모자랐습니다. 만들기 전에 견줘 본 프로젝트와 모자랐던 점입니다.

| 프로젝트 | 모자랐던 점 |
|---|---|
| [im-not-ai](https://github.com/epoko77-ai/im-not-ai) | 한국어 AI 말투를 잘 잡지만, 이미 쓴 글을 고쳐 쓰는 도구라 처음부터 문서와 독자에 맞게 쓰게 하지는 않음 |
| [patina](https://github.com/devswha/patina) | 한국어를 포함한 여러 언어의 AI 티를 지우지만, 역시 다 쓴 글을 고치는 도구 |
| [microsoft/PromptKit](https://github.com/microsoft/PromptKit) | 페르소나와 형식을 조립하지만 엔지니어링 문서용이고, 어법과 읽는 사람을 고르는 기능이 없음 |
| [simonpainter/tone](https://github.com/simonpainter/tone) | 공통 기준과 형식별 지침을 두지만 영어 전용이고 조립하는 엔진이 없음 |

docs-suit 는 쓰기 전에 문서 종류와 읽는 사람, 말투에 맞춰 규칙을 조립하고, 다 쓴 뒤에는 같은 규칙으로 잽니다.

## 글을 쓸수록 캐릭터가 자랍니다

처음에 학생, 개발자, 직장인 같은 클래스를 골라 캐릭터를 만듭니다. 규칙을 지킨 문서가 쌓이면 경험치가 올라 전직하고, 칭호와 꾸밀 거리가 열립니다. 캐릭터는 Claude Code 의 상태 줄에도 뜹니다.

## 지금은 한국어 판만 있습니다

규칙과 예문, 본문 검사가 모두 한국어 글에 맞춰져 있습니다. 영어 판은 엔진은 그대로 두고 영어 규칙 묶음을 더하는 방식으로 나중에 넣을 예정입니다.

> Currently Korean only. An English rule pack is planned.

## 빠른 시작

조립한 지침은 마크다운 한 장입니다. Claude Code, Codex, Cursor 같은 에이전트에는 스킬로 깔고, 웹 채팅에는 붙여 넣어 씁니다. 파이썬 3.9 이상만 있으면 됩니다.

```sh
git clone https://github.com/dodokim-lab/docs-suit.git && cd docs-suit && python3 suit.py bootstrap
```

`bootstrap` 이 클래스와 쓰는 AI 도구, 캐릭터의 머리 모양을 묻고 고른 도구에 스킬을 깝니다. 끝나면 그 도구를 새로 열고 "업무 보고 써 줘" 처럼 평소대로 부탁하면 됩니다. 스킬이 규칙을 조립해 따르고, 다 쓴 글을 재서 캐릭터를 키웁니다.

깐 스킬은 받은 폴더의 `suit.py` 를 부르니, 받은 폴더는 옮기거나 지우지 마세요.
