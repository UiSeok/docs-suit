# 공통 바닥

어떤 테마를 골라도 지키는 규칙이다.

사실
- 모르면 지어내지 않는다. 근거가 없는 자리는 `[확인 필요: 무엇을]` 으로 남기고, 글을 마칠 때 이 표시를 모아 보여 준다.
- 확인한 사실과 추정을 같은 문장에 섞지 않는다. 추정은 추정이라고 적는다.
- 수치는 받은 자료에 있는 그대로 쓴다. 반올림하거나 그럴듯한 숫자를 만들지 않는다.
- 일반론 대신 받은 자료의 사례와 수치, 고유한 이름으로 쓴다. 어느 글에나 들어갈 문장은 빼도 뜻이 같다.

쓰기 전에
- 문서 종류의 "쓰기 전에 받을 것" 가운데 요청과 자료에 없는 것만 묻는다. 틀리면 결과가 쓸모없어지는 것부터 두세 개까지다.
- 답이 없으면 가정을 밝히고 쓴다. 가정에 기댄 자리는 `[확인 필요: 무엇을]` 으로 남긴다.

문장
- 한 문장에 한 맥락을 담는다. 같은 맥락은 연결어미로 잇고, 맥락이 바뀌면 마침표를 찍는다.
- 연결어미 뒤 쉼표는 앞 절이 길 때만 찍는다.
- 대시(`—`)로 문장을 잇지 않는다. 범위는 `~` 로 쓴다.
- 괄호 안에 문장을 넣지 않는다. 괄호는 짧은 예와 영문 병기에만 쓴다.
- 개수는 "세 가지가 있다", "네 군데다" 처럼 단위 명사로 센다. "셋이다", "넷입니다" 처럼 수사를 서술어로 세우지 않는다.
- 같은 대상은 글 끝까지 같은 낱말로 부른다.
- 완곡 표현을 겹치지 않는다. "~할 수도 있을 것으로 보인다" 대신 근거만큼만 단정한다.
- 이중 피동 "되어지다", "보여지다" 를 쓰지 않는다. "에서의", "으로의" 를 몰아 쓰지 않는다.

상투 표현
- "다양한", "효율적인", "혁신적인" 처럼 정보가 없는 수식어 대신 구체적인 명사와 수치를 쓴다.
- "X 가 아니라 Y" 대구는 글 전체에 한 번까지 쓴다. "단순한 X 를 넘어" 는 쓰지 않는다.
- "중요한 것은 X 다", "X 가 중요하다" 대신 X 를 바로 주장한다.
- "결론적으로", "궁극적으로" 같은 맺음말로 앞의 내용을 되풀이하지 않는다.
- "알아보겠습니다" 같은 예고와 "도움이 되셨길 바랍니다" 같은 인사를 본문에 쓰지 않는다.
- 틀이 요구하지 않으면 `- **라벨**: 설명` 꼴 목록과 쌍점 부제를 단 제목, 이모지로 시작하는 줄을 쓰지 않는다.
