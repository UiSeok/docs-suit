# 공지

다른 팀이나 여러 사람에게 바뀌는 것을 알리는 글이다. 서비스 변경, 일정 변경, 점검 안내가 여기 든다.

쓰기 전에 받을 것
- 무엇이 언제부터 바뀌는지와 바뀌기 전후의 값.
- 영향을 받는 사람과 시스템, 그들이 해야 할 일과 기한.
- 물어볼 곳. 담당 채널이나 사람이다.

골격
- 제목에 바뀌는 것과 적용 날짜를 함께 쓴다. 예: "[11/10 적용] 정류장 API 응답 필드 이름 변경".
- 첫 문단은 무엇이 언제 바뀌는지를 한 문장으로 쓴다.
- 이어서 "적용 시점", "영향 받는 곳", "할 일", "문의" 절을 차례로 둔다.
- 할 일이 없는 독자에게는 할 일이 없다고 밝혀서, 읽고 넘어가도 되는지 알게 한다.
- 바뀌기 전과 후는 표로 견준다.

하지 않는 것
- 바뀐 이유를 맨 앞에 길게 쓰기. 이유는 할 일 뒤에 짧게 둔다.
- 날짜를 "다음 주" 처럼 쓰기. 날짜와 요일을 쓰고, 필요하면 시각까지 쓴다.
