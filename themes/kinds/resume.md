# 이력서

채용 담당자가 30초 안에 "이 사람이 무엇을 해결해 봤는가"를 알게 하는 문서다.

쓰기 전에 받을 것
- 지원 회사와 직무, 채용 공고 원문 전체. 요약본이 아니라 원문이어야 공고의 요구 기술과 인재상을 놓치지 않는다.
- 프로젝트 기록 원문. 트러블슈팅 메모, 회고, README 를 그대로 받는다.

골격
- 맨 위 요약은 세 줄 안쪽이다. 지원 직무, 가장 강한 경험 하나, 최근 동향에 맞는 경험을 쓴다. 요즘은 AI 를 써서 무언가를 해 본 경험을 반긴다.
- 프로젝트마다 경험을 세 개에서 네 개 고른다. 경험 하나는 문제 상황, 해결 방법, 효과의 세 줄이다.
  - 문제 상황: 어떤 문제가 생겼는가.
  - 해결 방법: 어떤 근거로 어떻게 풀었는가. 다른 대안이 있었다면 왜 이것을 골랐는가.
  - 효과: 개선 결과를 수치로 쓴다. 수치가 없으면 지어내지 말고 `[확인 필요: 측정값]` 으로 남긴다.
- 경험마다 자세한 기록으로 가는 링크를 단다. 세 줄로는 읽는 사람이 다 이해하지 못한다.
- 공고의 요구 기술과 인재상에 맞는 경험을 위로 올린다.

하지 않는 것
- 기능 개발 나열. "로그인 기능 구현" 은 누구나 쓴다. 그 기능을 만들다 부딪힌 문제를 쓴다.
- 면접에서 설명할 수 없는 문장. 면접관은 이력서에 적힌 것으로 묻는다.

다 쓴 뒤에 할 것
- 이 이력서로 면접관이 물을 꼬리 질문을 경험마다 세 개씩 뽑아 준다. 답은 사람이 자기 말로 연습한다.
